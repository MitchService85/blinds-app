# UI/UX audit — 2026-09-06

Walked every screen on a 375×812 viewport as each person who uses it, and
ranked friction by how often it is hit. The measurer's entry screen is used
hundreds of times a job, the admin's settings once; the order below follows
that.

## Measurer — unit entry (hundreds of times per job)

**Found.** The entry form was 2.2 screens tall with 58 buttons. Eight
per-window options were always expanded (quantity, chain length, longer
chain, motorized / measure / mount overrides, note), though a typical window
touches none of them. On a 375×812 phone that pushed the **fraction keys and
Clear under the Save bar**: the single most-used control on the screen
needed a scroll. Above the keypad, two utility rows (unit note, old blinds
removed) and a wrapping tag row cost another ~140px before a digit could be
tapped.

**Fixed.**
- Rare options fold into **More options**, collapsed by default. The row
  shows what is set ("×3 · 48" chain · Motorized") so nothing is hidden, and
  it opens itself when a window that uses any of them is loaded for edit.
  Deduct and Left control stay visible: they are common.
- **Old blinds removed** (install-phase bookkeeping) hides while measuring
  a unit that has none recorded.
- The **camera** is always available; it used to appear only after opening
  the text note, so the fastest kind of note had a hidden step.
- **Delete** on a window row now confirms. A measurement is minutes on a
  ladder; a 36px button beside Edit erased it silently.
- In list mode, **+ Add window** rides the floating bar instead of sitting
  under the last row, so a 12-window unit does not need a scroll to add.

**Left alone, deliberately.** The Width/Height segmented control and the
"Will save as 102-LR1" preview. Auto-advancing width→height was considered
and rejected: bays enter several widths before the height, and a wrong guess
there costs more taps than it saves.

## Installer — floor grid, install mode (hundreds of times)

**Found.** The Measure/Install toggle was 36px tall in 12px type, the
smallest target on a screen used with gloves. The bottom bar said **Save &
exit**, which teaches that work is unsaved until pressed; everything
autosaves on every tap and the help says so. An empty floor showed a lone
"+" with no hint.

**Fixed.** Toggle is 44px in 14px type. The bar says **Done** (it still
triggers a sync on the way out). An empty floor explains itself.

## Admin — new job, project hub (occasional)

**Found.** Every new floor started from blank defaults, so a ten-floor
tower meant filling roll, drive, measure, mount, fabric codes ten times
over, and the same on the project hub's Add floor.

**Fixed.** A new floor starts from the previous floor's defaults, in both
places. Change what differs, keep the rest.

## Dashboard (every open)

**Found.** The help button was 32px while everything beside it was 44px.
Floor chips read "Level 4 3/12 · 77" — the 77 was unlabelled.

**Fixed.** 44px; "· 77 blinds".

## PM — share link (occasional, external)

Audited as built today: one screen, one action, no sign-in. Floors sort
naturally (Level 2 before Level 10). Nothing changed.

## Consistency check

Primary actions are blue, secondary neutral, destructive red, across every
screen. Bottom bars are the one shared component and hide while typing.
Notes and pricing are edited in the page, never in a fixed overlay. Dark
mode covers every new element. Empty and loading states exist on every
screen that loads.

## Not done, and why

- **Keypad "Next" key.** Would save the reach to the Height segment. Skipped
  because the segment is also the only place the current field is *shown*;
  moving that into the keypad is a bigger change than this pass.
- **Job cost summary (.xlsx)** still sits beside the invoice list on the
  Money card. Redundant now that invoices exist; kept until Mike confirms he
  no longer opens it.
- **Sign-in prompt** is small text in the header. A first-run screen would
  be clearer, but the sandbox exists so a signed-out visitor is not lost.
